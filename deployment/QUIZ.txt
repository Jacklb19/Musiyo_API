REVIEWED GUIDE QUIZ — V1
GET /api/v1/guide/quiz?tour_key=KEY[&room_key=KEY]&schema_version=1
POST /api/v1/guide/quiz/answers: {schema_version:1,id:ID,option_id:ID}
Canonical contracts and synthetic examples live in contracts/. Schema additions
do not change the existing guide or Web/Unity selection bridge. Both quiz routes
share the guide's per-source limit; 429 includes Retry-After, with no auto retry.

Draft production is explicit, deterministic and read-only, without a provider:
python -m scripts.prepare_quiz --database EXTERNAL_DB --tour TOUR --output NEW_EXTERNAL_DRAFT_JSON
Questions identify the record of an exact documented_fact excerpt with a current
source. Options quote 3-4 distinct currently assistant-eligible record titles.
This is a conservative recognition baseline, not a generated pedagogical curriculum.
Private drafts contain option_elements, correct_option_id, evidence_hash and review
metadata. Never put them in public/, contracts/, Git or a Unity build.

Human review: inspect every question, option and explanation against its cited
source. After a real review, set state=reviewed, reviewed_by to the responsible
person and reviewed_at to the actual timezone-aware timestamp. Keep rejected
questions in draft. Do not manufacture a reviewer or auto-promote drafts.
The external review HTML is a convenience, never cultural acceptance by itself.
Select the reviewed external file via MUSIYO_QUIZ_BUNDLE before starting the API.
Unset configuration returns an empty quiz. A malformed selected bundle fails
closed. No database migration, import, reindex or live write is required.

Every GET and answer reloads the file, checks the tour/room association, current
assistant authorization for the source and every option record, current option
titles and exact evidence/source fingerprint. Changes/revocations remove stale
questions and return 404 for their answers. The public GET never sends the key.
Only the answer POST supplies correctness, explanation, exact quote and source.
No score, visitor identity, answer history or question logging is stored.
This file-based operator review is for the existing single-worker demo. It is
not an authenticated multiuser review console. Owner acceptance and Web/XR
integration remain separate checks. No reviewed cultural questions are shipped.
