LOCAL API / WEB SESSION — WINDOWS

One external JSON file selects the existing SQLite database, matching private
storage, guide configuration, API origin, Web origin, Web checkout and process
state directory. Copy deployment/local-session.example.json outside all repos and
replace its placeholders. Relative paths resolve beside that configuration file.
Use a separate external guide JSON: {"generation":"local","embeddings":"local"}.
This selects the accepted lexical/extractive baseline. The main preview already
has this index. No migration, import, model download or reindex runs at startup.

From the API checkout, in PowerShell with its .venv and the Web node_modules ready:
  ./scripts/local-session.ps1 -Action validate -Config EXTERNAL_SESSION_JSON
  ./scripts/local-session.ps1 -Action start -Config EXTERNAL_SESSION_JSON
  ./scripts/local-session.ps1 -Action health -Config EXTERNAL_SESSION_JSON
  ./scripts/local-session.ps1 -Action stop -Config EXTERNAL_SESSION_JSON

Validate checks paths, local origins, guide settings and selected schema in read
only mode. Start reuses scripts/start-local-api.ps1 for an owned API and launches
the installed Vite executable after the existing model-decoder predev step. It sets MUSIYO_DEV_API_TARGET in that process so it
wins over an old .env.local. Browser requests remain same-origin /api/v1. The native
base is the same api_origin plus /api/v1. This is a development operation, not a
public or native Unity runtime configuration implementation.

Health checks API and proxy health/readiness, selected current catalogue slugs and
museum-main. It does not treat guide.available as provider readiness. Test a guide
question separately. When adapting this launcher to another published tour, change
its explicit museum-main readiness check coherently.

Occupied ports cause refusal. To share a pre-existing API that the owner/Unity
still uses, first verify its process, selected database, storage and adapter setup,
then explicitly set reuse_existing_api=true. The session cannot read another
process's environment; catalogue equality is a useful check, not proof of identical
storage or guide configuration. Reused API is never stopped or reconfigured. When
it is absent, start refuses; after reviewing availability, set reuse_existing_api
back to false to launch the selected API. Before starting a new 8000 service after
reboot, inspect ports/processes again. No boot service is installed.

State/logs stay external. Stop validates PID, executable and UTC start instant for
all recorded processes before terminating any. It leaves data, models, backups and
reused services untouched. A changed configuration or PID refuses automatic stop.
Keep the original config for stopping the session. Inspect retained logs after any
startup failure. Health reports exited processes; stop cleans retained state.

Semantic retrieval remains optional and separate: use the existing evaluation copy
and its pinned embedding configuration after verifying the installed fingerprint.
Keep generation=local. Start the existing portable runtime explicitly with
scripts/local-model.ps1; never pull or resume models as part of session startup.
Selecting an index/model mismatch may abstain even with published catalogue records.
Never silently reindex or replace the main database. Any future index change needs
selected database backup, explicit command and real PostgreSQL persistence checks.

Web guide timeout is 15 seconds by default. Anonymous questions use canonical v1;
answered, abstained and provider_unavailable are HTTP 200. Transport/422/429 are
separate errors. A 429 uses Retry-After seconds (60 if missing/invalid). The question
is retained for manual retry; there is no automatic retry. Cancelling aborts the
request and discards late completions. It does not guarantee immediate server/GPU
cancellation. Catalogue, HTML detail and the existing player remain independent.

No player synchronization, binary distribution, Unity client, cloud provisioning,
external AI upload, paid plan or voice production is performed by this operation.

Read-only relevance evaluation
The lexical extractive guide matches limited regular Spanish number inflections
without changing local-hash-v1 vectors. Identity questions prefer current record
summaries. Ranking uses authorized passage text/title rather than source/credit
metadata. Every meaningful question term must match for lexical extraction; partial
topic overlap cannot infer support for an unmatched qualifier. This can abstain on
valid synonyms/complex verb forms. It is not a general Spanish language model.
The separate semantic adapter still uses its model fingerprint/similarity settings.

Keep the explicit question set outside the repository workspace. Its private test
format is {"schema_version":1,"cases":[{"id":"synthetic-case","request":CANONICAL_GUIDE_QUESTION,"expected_status":"answered","expected_citations":["EXPECTED_SLUG"]}]}.
Use abstained/provider_unavailable with an empty expected citation list for negatives.
The request uses the existing canonical GuideQuestion model; it is not a new public
contract. This internal evaluator uses GuideService directly, without API rate-limit
traffic, and records identifiers/states/citations/timing without answers or questions.
It opens the selected SQLite database in URI read-only mode, requires schema 0005,
refuses in-workspace inputs/outputs and never replaces an existing report.

  .venv/Scripts/python.exe -m scripts.evaluate_guide --database EXTERNAL_DATABASE --guide-config EXTERNAL_GUIDE_JSON --cases EXTERNAL_CASES_JSON --output NEW_EXTERNAL_REPORT

A zero exit status means expected statuses/citation identifiers matched and the
selected database hash stayed unchanged. It does not prove cultural correctness or
answer relevance. Review the actual passages in Web. No import, migration, reindex,
model pull, generative adapter or external upload is part of this evaluation.

Evidence review and installed generator evaluation
Use --repeats 2 to collect sequential observations. First observed is not proof of
cold model residency; measure neutral cold loads separately and record /api/ps.
--review-output NEW_EXTERNAL_JSON explicitly retains private questions, responses,
actual adapter evidence, source fingerprints, selected fragment ids and an unfilled
human review worksheet. The default report still contains no questions/answers.
Review every claim for support, relevance, attribution and appropriate abstention.
A status/citation match is never reported as cultural acceptance.

Only after explicit owner authorization, --allow-generative-evaluation accepts an
external generation=ollama configuration pinned to an already installed digest.
It does not download, reindex, migrate or change the shared visitor session. Keep
the rejected 0.6B generator inactive. A failed candidate must not replace the baseline.

Unscoped identity questions prefer the closest matching current title, so a named
subject is not displaced by a related object that merely mentions it. This changes
ranking only; index fingerprints and shared contracts remain unchanged.

Windows PowerShell 5.1: selected guide/database inspection uses a Python module;
there is no nested python -c quoting. Run validation before session start:
  powershell -NoProfile -File scripts/local-session.ps1 -Action validate -Config EXTERNAL_SESSION_JSON
  powershell -NoProfile -File scripts/local-session.ps1 -Action start -Config EXTERNAL_SESSION_JSON
Use health/stop with the same configuration. Do not replace state from old runs.

Contract export uses existing explicit checkouts, never inferred sibling names:
  python -m scripts.sync_contracts --target web --web WEB_CHECKOUT
Unity's owner runs --target unity --unity UNITY_CHECKOUT. All destinations are
validated before copying. The API/Web operator does not write to Unity.

OPTIONAL REVIEWED QUIZ SELECTION
The external session JSON may include quiz_bundle_path, absolute or relative to
that JSON. The selected file must exist outside the repositories and validate as
QuizBundle. local-session passes it explicitly to start-local-api -QuizBundle;
the launcher restores its prior process environment after exit. Omitting it
starts with no quiz bundle, regardless of an inherited MUSIYO_QUIZ_BUNDLE.
Changing session settings requires stopping the owned session under its original
configuration before saving the new selection. Preserve a dated config backup.
